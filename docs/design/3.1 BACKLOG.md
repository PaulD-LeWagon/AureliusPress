## P1: High Priority — Architecture

1. **Turbo Audit & ContentBlock Delete Refactor:** Two related issues surfaced during Sprint 8:
   - The Stimulus `nested-forms#remove` action does not connect reliably in Cuprite (ES module timing race with importmap). The ContentBlock DELETE specs work around this with `execute_script`, but the *user-facing* Remove button is unreliable in headless Chrome and may misbehave in other environments.
   - Trix editor content is not populated in its hidden input until user interaction, causing `validate_content_presence` failures on form submit in test environments.
   - **Root cause:** The ContentBlock remove/update flow is a JS-dependent interaction in an otherwise server-rendered, full-page-load app. It relies on Stimulus to set `_destroy`, which is fragile.
   - **Proposed fix:** Replace the Stimulus-driven `_destroy` approach with a direct `DELETE /cb/:id` Turbo Stream route that removes the block server-side and streams the DOM removal. The routes already exist (`resources :content_blocks, path: "cb", only: [:create, :update, :destroy]`) but have no controller. Create `ContentBlocksController` with a `destroy` action + `destroy.turbo_stream.erb` template (admin + public namespaces). Update the "Remove" button to a Turbo delete link.
   - **Scope:** This is a meaningful refactor. Estimate 3–4 pts. Plan into Sprint 9 or as a standalone sprint.

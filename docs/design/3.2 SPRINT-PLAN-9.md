### S9-01 · ContentBlock destroy — controllers + Turbo Stream templates + request specs · *3 pts*

**Problem:** The routes `DELETE /admin/document/blog-posts/:id/cb/:cb_id`, `DELETE /admin/document/pages/:id/cb/:cb_id`, `DELETE /blog-posts/:id/cb/:cb_id`, `DELETE /pages/:id/cb/:cb_id` all exist but route to a non-existent controller — 404 in production. The Sprint 8 workaround bypasses these routes entirely, using the parent document form's `_destroy` flag instead.

**Solution:** Create the missing `ContentBlocksController` in both namespaces with a single `destroy` action, and a corresponding `destroy.turbo_stream.erb` that streams removal of the block's DOM wrapper.

**Files to create:**
- `app/controllers/aurelius_press/admin/document/content_blocks_controller.rb`
- `app/controllers/aurelius_press/document/content_blocks_controller.rb`
- `app/views/aurelius_press/admin/document/content_blocks/destroy.turbo_stream.erb`
- `app/views/aurelius_press/document/content_blocks/destroy.turbo_stream.erb`
- `spec/requests/aurelius_press/admin/document/blog_post_content_blocks_spec.rb`
- `spec/requests/aurelius_press/document/blog_post_content_blocks_spec.rb`

**Controller shape (both namespaces follow the same pattern):**
```ruby
class AureliusPress::Admin::Document::ContentBlocksController < AureliusPress::Admin::ApplicationController
  before_action :set_content_block
  before_action :authenticate_user!

  def destroy
    authorize @content_block
    @content_block.destroy!
    respond_to do |format|
      format.turbo_stream
      format.html { redirect_back fallback_location: root_path }
    end
  end

  private

  def set_content_block
    @content_block = AureliusPress::ContentBlock::ContentBlock.find(params[:id])
  end
end
```

**Turbo Stream template shape:**
```erb
<%= turbo_stream.remove dom_id(@content_block) %>
```
*(The `_content_block.html.erb` partial wrapper must have `id: dom_id(content_block)` set for this to work — verify and add if missing.)*

**Acceptance criteria:**
- [ ] `DELETE /admin/document/blog-posts/:id/cb/:cb_id` as admin → destroys record, returns Turbo Stream `remove` action targeting the block's DOM ID
- [ ] `DELETE /admin/document/pages/:id/cb/:cb_id` as admin → same
- [ ] `DELETE /blog-posts/:id/cb/:cb_id` as document owner → destroys record, returns Turbo Stream `remove`
- [ ] `DELETE /pages/:id/cb/:cb_id` as document owner → destroys record, returns Turbo Stream `remove`
- [ ] Unauthenticated `DELETE` → redirects to sign-in (both namespaces)
- [ ] Non-owner authenticated user `DELETE` → 403 Pundit (both namespaces)
- [ ] Request specs written and green for all paths above
- [ ] Zero RuboCop offences on new files
- [ ] Zero Brakeman warnings on new files

### S9-02 · Update Remove button → Turbo delete link + clean 4 feature specs · *3 pts*

**Problem:** The Remove button in `_content_block_fields.html.erb` uses `data-action="nested-forms#remove"` (Stimulus), which is unreliable in Cuprite. All 4 ContentBlock management feature specs work around this with `execute_script` + `fill_in_rich_text_area " "` hacks.

**Solution:** For persisted ContentBlocks, replace the Stimulus button with a `link_to` using `data: { turbo_method: :delete }` pointing at the correct namespace destroy path. Keep the Stimulus button for new (unsaved) ContentBlocks, since those have no `id` and cannot hit the destroy route. Update all 4 feature specs to click the link and assert DOM removal.

**View change in `app/views/aurelius_press/admin/content_block/_content_block_fields.html.erb`:**
```erb
<%# Pass delete_path as a local — set by the parent document edit view %>
<% if form.object.persisted? && local_assigns[:delete_path] %>
  <%= link_to "Remove", delete_path,
              data: { turbo_method: :delete },
              class: "remove-content-block-link" %>
<% else %>
  <button type="button" data-action="nested-forms#remove">Remove</button>
<% end %>
```

Each parent document edit view (`admin/document/blog_posts/_form.html.erb`, etc.) must pass the correct `delete_path` local when rendering `_content_block_fields`.

**Feature spec change (all 4 specs — DELETE scenario):**
Replace the current workaround:
```ruby
# REMOVE:
fill_in_rich_text_area "Content", with: " "
page.execute_script(<<~JS)
  const wrapper = document.querySelector('.content-block-rich-text-block-fields');
  ...
JS
click_button "Update"
```
With:
```ruby
# ADD:
within(".content-block-rich-text-block-fields") do
  click_link "Remove"
end
expect(page).not_to have_css(".rich-text-block", wait: 5)
```

**Files to update:**
- `app/views/aurelius_press/admin/content_block/_content_block_fields.html.erb`
- `app/views/aurelius_press/admin/document/blog_posts/_form.html.erb` (pass `delete_path`)
- `app/views/aurelius_press/admin/document/pages/_form.html.erb` (pass `delete_path`)
- `app/views/aurelius_press/content_block/_content_block_fields.html.erb` (public namespace equivalent — verify exists)
- `spec/features/aurelius_press/admin/document/blog_post/content_block_management_spec.rb`
- `spec/features/aurelius_press/admin/document/page/content_block_management_spec.rb`
- `spec/features/aurelius_press/public/document/blog_post/content_block_management_spec.rb`
- `spec/features/aurelius_press/public/document/page/content_block_management_spec.rb`

**Acceptance criteria:**
- [ ] Clicking "Remove" on a persisted ContentBlock fires `DELETE` immediately (no "Update" needed)

### S9-03 · Turbo audit fixes — Reactions destroy stream + admin likes legacy UJS · *1 pt*

Two small defects found during the pre-sprint Turbo Audit. Both are trivial in isolation; bundled together for efficiency.

**Fix A — `community/reactions#destroy` returns `head :no_content` (GAP-1 in audit)**

The engagement bar is wrapped in `turbo_frame_tag dom_id(interactable, :engagement)`. `reactions#create` already responds with a Turbo Stream that replaces this frame. `reactions#destroy` inconsistently returns `head :no_content`, leaving the frame stale if the route is ever called directly.

Changes:
- Update `ReactionsController#destroy` to `respond_to { |f| f.turbo_stream; f.html { redirect_back ... } }`
- Create `app/views/aurelius_press/community/reactions/destroy.turbo_stream.erb` — mirrors `likes/destroy.turbo_stream.erb`: `turbo_stream.replace dom_id(@reactable, :engagement)`

**Fix B — `admin/community/likes/index.html.erb` legacy Rails UJS (BUG-1 in audit)**

Line 21 uses `method: :delete, data: { confirm: '...' }` — the Rails 5/6 `rails-ujs` pattern. `rails-ujs` is not in the importmap; this link fires as a plain GET in Rails 7 + Turbo, silently failing to delete.

Change:
- Update to `data: { turbo_method: :delete, turbo_confirm: '...' }` — matching the pattern used by every other delete link in the application.

**Files to update:**
- `app/controllers/aurelius_press/community/reactions_controller.rb`
- `app/views/aurelius_press/community/reactions/destroy.turbo_stream.erb` *(new)*
- `app/views/aurelius_press/admin/community/likes/index.html.erb`

**Acceptance criteria:**
- [ ] `DELETE /community/reactions/:id` as reaction owner → Turbo Stream replaces engagement bar frame
- [ ] `DELETE /community/reactions/:id` as non-owner → 403
- [ ] Admin likes index "Destroy" link fires `DELETE` (not GET) in the browser
- [ ] No regression on existing reactions specs
- [ ] Zero RuboCop offences

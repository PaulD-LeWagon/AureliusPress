# 1.2 Personas

## 1. The Administrator / Author
- **Role:** The primary creator and manager of content.
- **Needs:** Fast, friction-free content entry. Needs the ability to categorize content rapidly using an AJAX-driven taxonomy system. Needs to assemble rich documents via composable content blocks.
- **Permissions:** Full CRUD access to all Documents, Catalogue items, Taxonomy, and Site Settings.

## 2. The Community Member (User / Reader)
- **Role:** A registered user who actively participates in the ecosystem.
- **Needs:** The ability to engage with content through Reactions (emojis), Likes, and by leaving Comments or private Notes. Ability to join private or public Groups.
- **Permissions:** Can read public content, create engagement items (Likes/Comments), and manage their own profile and Journal Entries (which are strictly private to the owner).

## 3. The Public Reader (Guest)
- **Role:** Unauthenticated visitors discovering content on the web.
- **Needs:** Fast page loads, clean aesthetics (Tyrian Purple, minimalist layout), and a seamless reading experience.
- **Permissions:** Read-only access to published Documents and public Catalogue items. Cannot comment, like, or access the CMS.

## 4. The API Consumer
- **Role:** External services or decoupled frontend components.
- **Needs:** Fast, paginated JSON endpoints to retrieve Catalogue data (like Quotes) and Taxonomy data.
- **Permissions:** Read-only via `Api::V1` routes.

### S11-01 · Admin document bulk destroy — blog posts, pages, atomic blog posts · *5 pts*

**Problem:** Admin document index tables have no checkbox UI and no bulk delete route. Three feature specs are permanently skipped: `skip "Implement bulk actions scenario"` in `admin/document/blog_post/crud_management_spec.rb`, `admin/document/page/crud_management_spec.rb`, and `admin/document/atomic_blog_post/crud_management_spec.rb`.

**Note:** Admin document individual destroy actions are intentionally full-page redirects (per `docs/design/TURBO-AUDIT.md` Section 3 — CMS form context). Only the bulk destroy action uses a Turbo Stream response. Individual destroy is unchanged.

**Route changes (all 3 resources):**
```ruby
# config/routes.rb — inside admin > namespace :document
resources :blog_posts, path: "blog-posts" do
  collection do
    delete :bulk_destroy
  end
  # ... existing nested resources unchanged
end
# Same pattern for :pages and :atomic_blog_posts
```

This generates:
- `bulk_destroy_aurelius_press_admin_document_blog_posts DELETE /aurelius-press/admin/document/blog-posts`
- `bulk_destroy_aurelius_press_admin_document_pages DELETE /aurelius-press/admin/document/pages`
- `bulk_destroy_aurelius_press_admin_document_atomic_blog_posts DELETE /aurelius-press/admin/document/atomic-blog-posts`

**Controller action (same pattern for all 3):**
```ruby
def bulk_destroy
  authorize AureliusPress::Document::BlogPost, :destroy?, policy_class: AureliusPress::DocumentPolicy
  ids = Array(params[:blog_post_ids]).map(&:to_i)
  @blog_posts = AureliusPress::Document::BlogPost.where(id: ids)
  @blog_posts.destroy_all
  respond_to do |format|
    format.turbo_stream
    format.html { redirect_to aurelius_press_admin_document_blog_posts_url,
                               notice: "#{@blog_posts.size} blog post(s) deleted.",
                               status: :see_other }
  end
end
```

*(Use a class-level `authorize` — same pattern as `index` — rather than per-record, since admin users can delete any document. Policy already permits admins.)*

**Turbo Stream template (all 3 — multi-remove):**
```erb
<%# app/views/aurelius_press/admin/document/blog_posts/bulk_destroy.turbo_stream.erb %>
<% @blog_posts.each do |blog_post| %>
  <%= turbo_stream.remove dom_id(blog_post) %>
<% end %>
```

**View change — index.html.erb (all 3):**

Three changes per index view:
1. Add `dom_id` to the record `<tr>` (needed as Turbo Stream target)
2. Wrap the table + bulk action bar in `form_with` for the collection `DELETE`
3. Add a checkbox `<td>` as the first column of each row + a bulk action bar below the table

```erb
<%= form_with url: bulk_destroy_aurelius_press_admin_document_blog_posts_path,
              method: :delete,
              data: { turbo: true } do |f| %>
  <table class="table">
    <thead>
      <tr>
        <th><!-- checkbox col --></th>
        <th>Title</th>
        <!-- ... existing headers ... -->
      </tr>
    </thead>
    <tbody>
      <% @blog_posts.each do |blog_post| %>
        <tr id="<%= dom_id(blog_post) %>">
          <td><%= check_box_tag "blog_post_ids[]", blog_post.id, false %></td>
          <!-- ... existing cells unchanged ... -->
        </tr>
      <% end %>
    </tbody>
  </table>
  <div class="bulk-actions mt-2">
    <%= f.submit "Delete Selected",
                 data: { turbo_confirm: "Delete the selected blog posts? This cannot be undone." },
                 class: "button danger" %>
  </div>

```

### S11-03 *(stretch)* · Public document bulk destroy — blog posts, pages, atomic blog posts · *3 pts*

**Problem:** Three public document feature specs skip bulk action scenarios. Public bulk delete is owner-scoped — a user can only delete their own documents.

**Constraint:** Unlike admin bulk destroy, the `bulk_destroy` action must scope to the current user's records only. `AureliusPress::DocumentPolicy#destroy?` already enforces record ownership; for bulk, use `policy_scope` to pre-filter before destroying.

**Controller pattern (owner-scoped):**
```ruby
def bulk_destroy
  ids = Array(params[:blog_post_ids]).map(&:to_i)
  @blog_posts = policy_scope(AureliusPress::Document::BlogPost,
                              policy_scope_class: AureliusPress::DocumentPolicy::Scope)
                  .where(id: ids)
  @blog_posts.destroy_all
  respond_to do |format|
    format.turbo_stream
    format.html { redirect_to aurelius_press_blog_posts_path,
                               notice: "#{@blog_posts.size} blog post(s) deleted." }
  end
end
```

*(No per-record `authorize` loop needed — `policy_scope` already restricts to the owner's records before `where(id: ids)` applies.)*

**Note:** Public document index `<tr>` rows already have `dom_id` wrappers (added in S10-03).

**Files to create/update:**
- `config/routes.rb` (add `collection { delete :bulk_destroy }` to public blog_posts, pages, atomic_blog_posts)
- 3 public document controllers: add `bulk_destroy` action
- 3 `bulk_destroy.turbo_stream.erb` templates
- 3 public document index views: add form wrapper, checkbox column, bulk action bar
- 3 request spec files: add bulk_destroy Turbo Stream scenario
- 3 feature specs: unskip and implement public bulk action scenarios

**Acceptance criteria:**
- [ ] `DELETE /blog-posts` with `blog_post_ids[]` as owner → Turbo Stream removes only owner's selected rows
- [ ] IDs belonging to another user are silently ignored (scoped out before destroy)
- [ ] Unauthenticated `DELETE` → sign-in redirect
- [ ] 3 public feature specs unskipped and passing
- [ ] Zero RuboCop offences

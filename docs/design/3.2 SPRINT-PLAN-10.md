### S10-01 · Admin fragment moderation — Turbo Stream row removal · *2 pts*

**Problem:** `admin/fragment/comments#destroy` and `admin/fragment/notes#destroy` both call `@record.discard` then `redirect_to index`. When an admin moderates content from the index table, the whole page reloads and scroll position is lost.

**Bundled security fix:** `admin/fragment/notes#destroy` does not call `authorize @note` — this is an omission compared to `comments#destroy` which does. Fix must be included in this story.

**Solution:** Add a `respond_to` block to each destroy action, create `destroy.turbo_stream.erb` templates that remove the discarded row by `dom_id`, and add `id: dom_id(record)` to each `<tr>` in the index views.

**Controller change (both):**
```ruby
def destroy
  authorize @comment  # (or @note — already present on comments; add to notes)
  @comment.discard
  respond_to do |format|
    format.turbo_stream
    format.html { redirect_to aurelius_press_admin_fragment_comments_url, notice: "Comment discarded." }
  end
end
```

**Turbo Stream template (both — mirrors the pattern):**
```erb
<%= turbo_stream.remove dom_id(@comment) %>
```

**Index view change (both — add `id:` to the record `<tr>`):**
```erb
<tr id="<%= dom_id(comment) %>">
```

**Files to update:**
- `app/controllers/aurelius_press/admin/fragment/comments_controller.rb`
- `app/controllers/aurelius_press/admin/fragment/notes_controller.rb` (+ add missing `authorize @note`)
- `app/views/aurelius_press/admin/fragment/comments/destroy.turbo_stream.erb` *(new)*
- `app/views/aurelius_press/admin/fragment/notes/destroy.turbo_stream.erb` *(new)*
- `app/views/aurelius_press/admin/fragment/comments/index.html.erb` (add `id: dom_id(comment)` to `<tr>`)
- `app/views/aurelius_press/admin/fragment/notes/index.html.erb` (add `id: dom_id(note)` to `<tr>`)
- `spec/requests/aurelius_press/admin/fragment/comments_spec.rb` (add/update destroy scenarios)
- `spec/requests/aurelius_press/admin/fragment/notes_spec.rb` (add/update destroy scenarios)

**Acceptance criteria:**
- [ ] Admin discards a comment → row removed from DOM via Turbo Stream (no full-page reload)
- [ ] Admin discards a note → row removed from DOM via Turbo Stream
- [ ] Non-admin `DELETE` on comments → 403 Pundit
- [ ] Non-admin `DELETE` on notes → 403 Pundit (requires adding missing `authorize @note`)

- [ ] Request specs green for both controllers covering all paths

### S10-02 · Admin index tables — Turbo Stream `<tr>` removal on destroy · *5 pts*

**Problem:** The six admin index tables (authors, sources, quotes, tags, categories, users) all redirect to the index after `destroy!`. The delete links correctly use `data: { turbo_method: :delete }`, but the controllers only respond with `redirect_to`, so Turbo Drive performs a full navigation. Adding `destroy.turbo_stream.erb` + `dom_id` wrappers enables inline row removal.

**Note on authorization:** `sources_controller#destroy` and `quotes_controller#destroy` do not call `authorize` — this is an existing omission. Do not add or change authorization patterns in this story; authorization is outside this sprint's scope. Only add the Turbo Stream response path.

**Pattern (same for all 6 controllers):**

```ruby
def destroy
  # existing authorize call (where present) stays untouched
  @author.destroy!
  respond_to do |format|
    format.turbo_stream
    format.html { redirect_to aurelius_press_admin_catalogue_authors_url, notice: "...", status: :see_other }
  end
end
```

**Turbo Stream template (each — filename mirrors the controller namespace):**
```erb
<%= turbo_stream.remove dom_id(@author) %>
```

## Sprint Retrospective

*(To be completed at sprint close)*

**What shipped?**
> All 10 pts delivered — 7 committed plus the stretch story. S10-01 added Turbo Stream row removal to admin fragment moderation (comments and notes), and bundled the missing `authorize @note` security fix that had been silently omitted. S10-02 wired Turbo Stream `<tr>` removal to all 6 admin index controllers (authors, sources, quotes, tags, categories, users) — 6 templates, 6 controller `respond_to` blocks, 6 index view `dom_id` wrappers, all covered by new or extended request specs. S10-03 (stretch) applied the same pattern to the 3 public document controllers (blog posts, pages, journal entries). Nine feature specs required updating to assert DOM removal instead of flash messages — the correct assertion pattern for Turbo Stream deletes where no redirect fires.

**What slowed us down?**
> The feature spec rework was the only unexpected work. Pre-existing specs asserted flash messages from redirects; after the Turbo Stream upgrade those assertions became wrong. Specs deleting from show/edit pages (fragment moderation, user edit, blog post show, journal entry show) needed special handling — navigating to the index or checking the DB directly. Pattern: any time Turbo Streams replace a redirect, feature specs that relied on the redirect's flash need to be rewritten to assert DOM or DB state instead.

**What changes next sprint?**
> The entire P2 Turbo polish backlog is now cleared. Only the icebox remains (Bulk Ops epic, Devise confirmable, structured logging). Next sprint should be Bulk Operations (BULK-01, minimum 8 pts) or the auth audit for the missing `authorize` calls in sources/quotes controllers.

# 2.3 System Architecture

The application is a Ruby on Rails application using the MVC architectural pattern, heavily namespaced under `aurelius_press`.

## Routing & Namespaces

The routing structure divides the application into distinct functional areas:

1. **`admin` Namespace:**
   - Provides CMS (Content Management System) functionality.
   - Comprehensive CRUD routing for `documents`, `catalogue`, `taxonomy`, `community`, `fragments`, `users`, and `settings`.
   - Used by administrators, moderators, and content managers to mutate the underlying data.
   - **Site Settings:** The `admin/settings` resource manages `AureliusPress::SiteSetting` — a key-value store for admin-configurable platform settings (site name, feature flags, etc.). Supports `index`, `edit`, and `update` actions only (no creation or deletion via UI — settings are seeded).

2. **Public / Feature Namespaces:**
   - **`catalogue`**: Read-only views for `authors`, `sources`, and `quotes`. Includes nested routes for users to leave `comments` and `notes`.
   - **`taxonomy`**: Read-only views for `tags` and `categories`.
   - **`community`**: Routes for `groups`, `group_memberships`, `likes`, and `reactions`.
   - **Concrete Documents**: Direct routes at the top-level (inside the engine/namespace) for `blog_posts`, `atomic_blog_posts`, `pages`, and `journal_entries` (which are owner-only). Contains deeply nested routing for inline `content_blocks` and associated `comments`/`notes`.

3. **API V1:**
   - JSON endpoints (`api/v1`) for taxonomy (tags, categories) and catalogue (quotes), likely used for dynamic frontend typeaheads or decoupled consumers.

4. **Authentication:**
   - Handled via Devise routes mapped to `aurelius-press/users`.

## Component Responsibilities

- **Controllers:** Follow RESTful conventions. Controllers are segmented by access level (Admin vs Public).
- **Views:** Uses Rails views with Hotwire (Turbo + Stimulus) for SPA-like responsiveness without full React/Vue frontends.
- **Authorization Layer:** Pundit policies strictly map to controllers (e.g., `CommentPolicy`, `GroupPolicy`) to enforce permissions based on the user's role and the resource's privacy settings.
- **Data Persistence:** Active Record with a heavy reliance on polymorphic associations and Single Table Inheritance (STI) to keep tables minimal while supporting a variety of content forms (e.g., all user engagement is stored in `fragments`, all pages/posts are `documents`).

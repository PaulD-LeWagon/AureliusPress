# 2.5 UI Design Brief

This document captures the current design system, component inventory, and styling conventions for AureliusPress, and sets the direction for the NanoCSS migration.

---

## CSS Framework Strategy

### Current: PicoCSS
AureliusPress currently uses `@picocss/pico` (v2) as its base CSS framework. PicoCSS is classless/minimal — it styles semantic HTML elements directly, requiring no utility classes for baseline layout and typography.

**Configuration** (in `application.scss`):
- CSS variable prefix: `--ap-` (e.g., `--ap-primary`, `--ap-spacing`)
- Responsive spacings enabled
- Default theme module disabled (overridden by the Tyrian Purple custom theme)

### Target: NanoCSS
**NanoCSS is the intended long-term CSS framework.** PicoCSS was selected for rapid prototyping. As the product matures, components will be incrementally migrated to NanoCSS for its lower footprint and composability.

**Migration rules:**
- Do not add new PicoCSS-specific class patterns
- Retain the `--ap-` CSS variable prefix throughout the migration
- New custom components should be built on NanoCSS from the start
- Existing ViewComponents will be retrofitted to NanoCSS progressively

## Design Tokens

All tokens are defined as SCSS variables in `app/assets/stylesheets/partials/_variables.scss` and exposed as CSS custom properties via the Tyrian Purple theme.

### Spacing
| Token | Value |
|-------|-------|
| `$spacing-base` | `1rem` |
| `$spacing-half` | `0.5rem` |
| `$spacing-quarter` | `0.25rem` |
| `$spacing-three-quarters` | `0.75rem` |
| `$spacing-double` | `2rem` |

### Borders
| Token | Value |
|-------|-------|
| `$border-radius-base` | `0.75rem` |
| `$border-width-base` | `1px` |
| `--ap-border-radius` | `0.25rem` (PicoCSS default, overridden per component) |

### Shadows
| Token | Value |
|-------|-------|
| `$box-shadow-base` | `0 0.125rem 0.25rem rgba(0,0,0,0.2)` |
| `$box-shadow-hover-base` | `0 0.25rem 0.5rem rgba(0,0,0,0.35)` |

### Transitions
| Token | Value |
|-------|-------|
| `$transition-base` | `all 0.2s ease-in-out` |

### Card Dimensions
| Token | Value |
|-------|-------|
| `$tile-card-width` | `17rem` |
| `$tile-card-height` | `$tile-card-width * 0.667` (2:3 ratio) |

## Theming

### Tyrian Purple Theme
The active theme is **Tyrian Purple**, defined in `app/assets/stylesheets/themes/tyrian_purple/`.

| File | Purpose |
|------|---------|
| `_light.scss` | Light mode colour overrides |
| `_dark.scss` | Dark mode colour overrides |
| `_schemes.scss` | Media query wiring for light/dark |
| `_styles.scss` | Typography, borders, transitions, icon SVGs |
| `_theme-colors.scss` | Colour palette definitions |
| `_tyrian-purple.scss` | Root entry point (`@use` both `styles` and `schemes`) |

**Typography:**
- Body: Open Sans → Lato → Roboto → system-ui (sans-serif stack)
- Headings: Merriweather → Luxurious Roman → Georgia (serif)
- Cursive: Quintessential → Dancing Script → Sacramento
- Monospace: ui-monospace → SFMono → Menlo → Consolas

**Heading scale:**
| Element | Size | Line Height |
|---------|------|-------------|
| `h1` | `2.25rem` | `1.125` |
| `h2` | `1.75rem` | `1.15` |
| `h3` | `1.5rem` | `1.175` |
| `h4` | `1.25rem` | `1.2` |
| `h5` | `1.125rem` | `1.225` |
| `h6` | `1rem` | `1.25` |

## ViewComponent Inventory

All components inherit from `ApplicationComponent < ViewComponent::Base`. `ApplicationComponent` provides:
- `html_attributes(hash)` — renders a hash as HTML attribute string (handles data-*, style, boolean attrs, kebab-case conversion)
- `merge_classes(*args)` — concatenates CSS class strings
- `merge_hashes(hash, *args)` — deep-merges HTML option hashes

Components live in `app/components/` (intentionally not namespaced — no model coupling).

### `CardComponent`
Renders an `<article>` with optional header (title/subtitle), content section, and footer CTAs.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `src` | String | `""` | Background image URL |
| `title` | String\|nil | `nil` | Card heading |
| `subtitle` | String\|nil | `nil` | Card subheading |
| `ctas` | Array<Hash> | `[]` | Call-to-action links (`href`, `text`, `class`, `role`) |
| `css_class` | String | `""` | Additional CSS classes |
| `html_options` | Hash | `{}` | Extra HTML attributes |

**Variant:** `.tile` — fixed-dimension (17rem × ~11.3rem) card where the entire surface is a link.

### `CardTileComponent`
Specialised tile variant of CardComponent. Fixed 2:3 aspect ratio, full-surface link.

### `NavComponent`
Renders a `<nav>` with branded title, a pages dropdown, and an admin dropdown (conditional).

| Prop | Type | Description |
|------|------|-------------|
| `title` | String | Brand/site name in the nav bar |
| `nav_items` | Hash | `{ pages: [{href:, text:}], admin: [{href:, text:}] }` |
| `css_class` | String | Additional classes |

### `HeroComponent`
Full-width hero banner with background image support.

### `AccordionComponent`
Disclosure pattern using HTML `<details>/<summary>`.

### `DropdownComponent`
Dropdown menu, composable into NavComponent.

### `HeaderGroupComponent`
`<hgroup>` wrapper for page-level title + subtitle pairs.

### `LogoComponent`
Site logo/brand mark renderer.

### `SimpleFooterComponent`
Minimal page footer.

## Key UI Patterns

### Content Blocks
Rendered as `<div class="content-block">` with a "Content Block" label header (PicoCSS primary colour). Fields inside use `.content-block-fields` with a top border separator. Target for NanoCSS migration.

### Forms
- Uses SimpleForm with PicoCSS-compatible markup.
- Form actions wrapped in `.form-actions` with `margin-top: $spacing-base`.
- Rich text inputs use ActionText / Trix editor. The Trix editor is styled via `actiontext.css` and forced white text (`.trix-content { color: white !important }`).
- Hint text: `<span class="hint">` — italic, 0.875rem, secondary colour.

### Flash Messages
Rendered via `layouts/_flash_messages.html.erb`.

### Navigation
Full nav rendered via `layouts/_navigation.html.erb`, backed by `NavComponent`. Dropdowns use PicoCSS `<details class="dropdown">` pattern — will migrate to NanoCSS equivalents.

### Engagement Bar
Likes and reactions rendered via `aurelius_press/community/shared/_engagement_bar.html.erb`, styled in `engagement.scss`.

### Footer
`footer.main` — primary colour background, full-width, centred text, min-height `12rem`.

## Accessibility & Responsiveness

- PicoCSS provides semantic-HTML-first accessibility baseline (ARIA roles on interactive elements, focus styles).
- Responsive spacings enabled via PicoCSS breakpoints (sm → xxl multipliers: 1×, 1.25×, 1.5×, 1.75×, 2×, 2.25×).
- Search inputs use `border-radius: 5rem` (pill shape) per PicoCSS convention.
- Colour contrast is enforced through the Tyrian Purple theme — dark/light schemes are toggled via `prefers-color-scheme`.

## Future Work (NanoCSS Migration)

When migrating a component from PicoCSS to NanoCSS:
1. Remove any PicoCSS-specific semantic class reliance from the component template.
2. Replace with NanoCSS utility classes or custom component CSS.
3. Retain `--ap-` CSS variable references for design token continuity.
4. Update the corresponding `_*.scss` file in `view_components/`.
5. Run the full RSpec + Capybara suite to verify no visual regressions in feature specs.
